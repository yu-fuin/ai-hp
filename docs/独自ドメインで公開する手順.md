# 独自ドメインで公開する手順（メモ）

お客様がドメインを取得したときに使う。内容は一般的な手順のみ（会社名・個人情報は書かない）。

## 前提
- GitHub Pages は独自ドメインに対応している。SSL（https）は無料で自動。
- 1つのリポジトリにつき、独自ドメインは1つだけ。
- このリポジトリ（ai-hp）には複数の会社が入っているので、そのまま独自ドメインを付けると
  `https://ドメイン/clients/c番号/` というURLになり、きれいではない。
- ai-hp は誰でも見られる（公開）ので、ヒアリングシートの内容も見える。お客様の情報に注意。

## 進め方（おすすめ：会社ごとに公開用リポジトリを別に作る）
1. ドメインを取る（お名前.com、ムームードメイン、Cloudflare Registrar など）
2. 公開用の新しいリポジトリを作る（例：`c001-site`）
3. `clients/c番号/` の中身のうち、公開するものだけをコピーする
   （`hearing.md` は入れない）
4. 公開用リポジトリで GitHub Pages を有効にする（Settings → Pages → main / root）
5. ドメインの管理画面で、DNS を設定する
   - Aレコード（4つ）：`185.199.108.153` / `185.199.109.153` / `185.199.110.153` / `185.199.111.153`
   - www を使う場合：CNAME `www` → `yu-fuin.github.io`
6. 公開用リポジトリの Settings → Pages → Custom domain に、ドメインを入れて Save
7. 数分〜最大24時間待って、「Enforce HTTPS」にチェックを入れる

## 公開前に直すこと
- 「要確認」の項目をすべて埋める（電話番号・番地・定休日・採用条件など）
- `index.html` の `og:url` と `og:image` を、取ったドメインのURLに直す
- 電話番号を `tel:` のリンクにする（右上・お問い合わせ・フッター）
- AI画像は本物の写真に差し替える（または「イメージ画像」の表示を残す）
- お問い合わせフォームが必要なら、別のフォームサービスを使う（HTMLだけでは送信できない）
- メールアドレス（info@〜）が必要なら、別にメールサービスを用意する

## 費用の目安
- ドメイン代のみ（.com で年1,500円前後、.jp で年3,000円前後）
- 公開（GitHub Pages）は無料

## 別の方法
- Cloudflare Pages / Netlify などは、1つのリポジトリのフォルダ単位で公開できる（別サービスの登録が必要）

## 依頼されたときのClaudeの動き
- 「c番号を公開用リポジトリに切り出す準備をして」と言われたら、上の手順3までを案内・実行する
- 新しいリポジトリの作成には、GitHub側の権限追加が必要になるので、そのとき案内する
